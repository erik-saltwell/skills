# Setup Project

Install the work-item conventions without requiring the user to choose paths or Markdown formats. This sets up workflow documentation, not an application scaffold.

1. Resolve the target project from the user's request or current workspace. Use the Git root when working inside a repository; otherwise use the selected project directory. Read applicable instructions and any existing work-item workflow before changing files.
2. Read [assets/workflow.md](assets/workflow.md). This is the default project workflow. On repeat setup, merge missing registration and optional quality-rubric conventions into the existing workflow while preserving project customizations. Reconcile obsolete default rules that require every item to have `item.md`, rebuild the index exclusively from those records, treat rubric definition as a required first stage, or use a `defining-success` status; do not silently replace the whole workflow with the template.
3. Run the bundled helper with the resolved project path:

   ```sh
   python3 <this-skill-directory>/scripts/setup_project.py /absolute/project/path
   ```

   Resolve the helper relative to this installed skill, including when the skill is a symlink. It creates `.work-items/`, copies the workflow only if missing, creates an empty root `WORK-ITEMS.md` only if missing, and creates root `.agent_context.md` with just its heading only if missing. It updates the existing marked reference block in each agent file, migrating old workflow imports to work-item pointers. `CLAUDE.md` and `GEMINI.md` import `.agent_context.md` every turn using `@.agent_context.md`; `AGENTS.md` instructs Codex to read and follow it before starting work. All three point to `.work-items/workflow.md` for registering, saving, listing, resuming, or changing work-item status, and for planning or implementing tracked work. AGENTS.md uses Markdown links with paths resolved relative to the file. It preserves content outside those blocks, existing context, and work items. Run it directly within the user's setup request; no separate draft approval is needed.
4. Inspect the result. If the helper stops on an existing symlink or malformed reference block, inspect it and complete the same narrowly scoped setup manually, preserving shared targets and project content. This does not by itself require additional user approval. Each agent instruction file must direct the agent to read the same project workflow. If pre-existing instructions contradict that workflow, reconcile the relevant text using the user's established preferences and preserve unrelated instructions. If existing items predate the index, rebuild its table from their `item.md` records using the workflow's index rules; never leave them hidden behind an empty table.
5. Consolidate any duplicated workflow instructions outside the managed blocks into `.work-items/workflow.md`, preserving project-specific workflow customizations before removing their duplicate text. Leave unrelated or agent-specific instructions in place. Keep `.agent_context.md` user-maintained: do not populate it with inferred project facts, overwrite existing content, or move unrelated instructions into it automatically. Avoid import cycles: neither shared file should import the agent entry files. All workflow rules belong in the workflow; the managed blocks contain only imports or read directives.
6. Verify all three agent files load `.agent_context.md` every turn and reach `.work-items/workflow.md` through the work-item pointer, with no workflow import in their managed blocks. Verify the context, workflow, and index exist, and there are no example items or duplicate reference blocks. Preserve registered rows without `item.md` when reconciling the table; these are valid registrations, not broken records. Move items recorded as `defining-success` to `captured` and keep any existing `rubric.md` files in place rather than deleting them. Do not backfill rubrics or item records for existing items or reopen completed work. Report the created or updated paths, identify `.agent_context.md` as the user's project-context file to fill in, and give a short example: `Use setup-workitem to register CSV export.`

Do not create a work item for setup itself, install other skills, alter ignore rules, initialize Git, or commit changes as a side effect. Workflow files are intended to be versioned with the project. Existing conversational skills remain optional: the project workflow supplies enough guidance to operate when they are unavailable.
